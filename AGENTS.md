# AGENTS.md

Guidance for coding agents working in this repository. stackkit is a Claude Code plugin. Two parts, edited differently:

- **`skills/`** — the plugin. `bootstrap/` runs the interview and hands the confirmed plan to `create/`, whose scripts (standard library only, run via `uv run --no-project`) do the copy, removal and renaming, or with `--add` grow an existing project by merging in the parts it gains (`bootstrap.py`) and the install and checks (`check.py`, which ends with `status.py`'s read-only report of what's left to set up). A third skill, `status/`, reruns that report any time and prints the checklist and cost estimate; costs live in `skills/create/costs.md`. They're two skills because a skill's `allowed-tools` approval lasts only for the turn it's invoked in, and the interview spans many turns; `create` is invoked in the turn the plan is confirmed, so the whole build runs without permission prompts. Keep every command `create` runs inside one of its two scripts.
- **`template/`** — the product: the stack every new project is copied from. It has its own `AGENTS.md` for working *inside* it. It must stay runnable as-is (`make check` passes in a plain copy), so never add render syntax to it.

## Rules

- **No employer information** anywhere in this repo or the template — no employer names, domains, emails, repos, or employer-specific formats, not even as defaults to be rewritten. Use `example.com` and blank defaults.
- **A module's footprint lives in `template/stackkit.toml` and in `stackkit:begin/end <name>` markers.** When you add or change anything a module touches in a shared file, wrap it in that module's markers and update its `refs`.
- **Shared Google clients live in `template/shared/gcp_services/`.** Every `*_service/` folder keeps an exact copy (`shared/sync.sh`), because each deploys from its own folder. Edit `shared/`, then run `make sync` in the template; a manifest path under `shared/` also removes each copy.
- **After any change to `template/` or the scripts, run `make test-bootstrap`.** It lints the scripts and template (a ruff fix that moves imports would move the markers above them), bootstraps the sample projects in `SAMPLE_SPECS` (between them, every module kept and removed), fails if a removed module is still mentioned outside Markdown, runs `make check` and `make build` in each, converts one existing repo in place, and checks that adding parts to a project gives the same result as building it with them. New builds delete self-contained Markdown lines (table rows, list items, example code) that mention removed modules; prose is left for `create` to reword.
- **Emulator tool versions live in one place:** `JAVA_MIN` / `NODE_MIN` and the install commands in `skills/create/scripts/status.py`. The skills relay its output and never hard-code versions; `template/docs/ENVIRONMENTS.md` repeats them in its install steps. `make check-versions` (run by `make test-bootstrap`) fails when the latest Firebase CLI needs something newer, or the docs don't match.
- Research lives in `docs/research/`; its charter sets scope and constraints.
